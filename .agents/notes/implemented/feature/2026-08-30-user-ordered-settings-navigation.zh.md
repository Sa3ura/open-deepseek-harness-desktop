# Agent Note: 用户可排序的设置导航

Status: implemented

[English](2026-08-30-user-ordered-settings-navigation.md) | 中文

## Problem

设置分区由彼此独立的插件动态贡献。规范注册顺序适合作为默认值，但插件较多时，常用页面可能不方便触达。若用显示文字或数组下标保存偏好，在切换语言或卸载插件时就会失效。

## Decision

设置外壳为每个分区行提供独立的三横线排序把手，并提供等价的上、下方向键操作。Pointer Capture 只能从把手开始；移动超过 4px 后，固定定位的完整行浮层会跟随鼠标，测量过的相邻行则平移并让出原位置。靠近边缘可自动滚动长导航栏。最终顺序会等待 180ms 落位动画结束后一次性写入；释放到区域外、按 Escape 或收到指针取消事件时只回弹、不写入。插入线使用主题文字 token，因此浅色模式为黑色、深色模式为白色；减少动态效果偏好会移除过渡动画。

结果以稳定的 `settings.section` ID 持久化到 Host 持有的 `ui-settings-navigation.sectionOrder` 设置中。分区选择仍由单独按钮负责，因此普通页面导航不会误触拖动。

持久化顺序叠加在实时 slot 账本之上，而不修改账本本身。已知 ID 按用户顺序出现；新注册 ID 按规范账本顺序追加；暂时缺失的 ID 保留在持久列表中，以便插件重新安装后恢复。投影时会忽略空 ID 和重复 ID。

## Alternatives considered

**修改每个插件的注册顺序。** 这会把用户偏好变成共享插件策略，还需要跨越彼此独立的包协调写入。

**保存显示文字或可见下标。** 文字会随语言变化，而每当插件出现或消失时下标都会移动，两种方案都可能静默排错页面。

**使用浏览器本地存储。** 这会绕过既有设置文档，使偏好脱离当前选择的桌面数据目录，并让导入与复用行为和其他 UI 偏好不一致。

## Consequences

用户可用指针或键盘按自己的工作流整理较长的设置栏，在释放前就能看到被跨越项目完整让位，并通过当前设置提供方在重载后保留顺序。动态插件注册无需迁移即可继续工作。代价是增加一个很小的持久化命名空间、排序期间的临时指针几何信息，并在设置账本变化时执行一次顺序叠加；规范注册顺序仍是回退值和新分区的顺序来源。
