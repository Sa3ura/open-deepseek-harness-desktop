# Agent Note: 经验证的桌面端数据来源选择

Status: implemented

[English](2026-08-26-desktop-data-source-selection.md) | 中文

## Problem

首次启动的桌面端选择页把默认 `~/.dsh` 中任何非空内容都视为官方 Harness 数据，并在该目录不存在或为空时完全跳过选择页。使用自定义 `DSH_HOME`、便携目录或备份的用户无法选择自己的位置，无关文件却可能错误开放导入与复用操作，直到后续阶段才失败。

## Decision

桌面端独立 Harness home 没有既有选择或数据时，选择页始终打开。数据来源面板说明默认位置是否包含可识别的 Harness 状态，并在所有状态下保留目录选择入口。识别到默认来源时预选导入到独立环境；默认来源缺失或无法读取时预选全新开始，同时允许用户通过目录选择器启用导入或直接使用。

Electron 负责目录选择与验证。所选目录自身或其 `.dsh` 子目录包含受支持用户数据或 Profile 时才会被识别。渲染层只接收规范化结果，并提交模式与来源；Electron 在导入或复用前再次解析并验证来源。空目录、无关目录和无法读取的目录留在选择页，并显示范围明确的修正提示。

独立导入从检测到的默认来源或用户选择的自定义来源复制到桌面端独立 home。直接使用会把规范化的自定义来源记录为活动 `DSH_HOME`；启动时会在复用前验证该记录，因此目录被移动或失去读取权限后会重新进入选择页。全新开始不需要来源。现有语言选择与三种数据策略在所有首次启动状态下均保持可用。

## Alternatives considered

**把“自行导入”增加为第四种数据策略：** 否决，因为目录位置与数据共享方式是两个独立决定。始终显示的数据来源面板可以开放自定义路径，无需建立语义完全相同的第二种导入模式。

**默认 `~/.dsh` 不存在时隐藏导入与复用：** 否决，因为默认位置缺失不能证明用户从未使用 DSH。这两个操作会先打开目录选择器，成功选择后才进入选中状态。

**接受任意非空目录：** 否决，因为无关文件不能证明目录是可用的 Harness home，并会把本可立即修正的错误推迟到导入或启动阶段。

## Consequences

- 没有官方 DSH 数据的首次用户仍能看到支持语言切换的选择页，并可直接进入全新配置。
- 使用默认或自定义 Harness home 的用户都能选择独立导入，或明确共享所选目录。
- 用户选择 home 上级目录时，只要其中 `.dsh` 包含可识别数据，就会自动解析到该子目录。
- 只有不受支持文件的目录不能导入或直接使用。
- 自定义复用路径会持久保存，但目录移动或权限撤销后必须重新选择来源。
