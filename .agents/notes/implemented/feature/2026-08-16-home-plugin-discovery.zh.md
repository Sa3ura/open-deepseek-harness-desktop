# Agent Note：主页插件发现

状态：已实现

[English](2026-08-16-home-plugin-discovery.md) | 中文

## 问题

新会话主页没有展示 Harness 插件生态。用户必须在产品外寻找社区项目，自行区分可安装的 DSH 插件与 GitHub 专题中的无关结果，并在缺少产品内来源和安全提示的情况下抄写安装命令。

## 决策

会话拥有方在 Workspace 和 Agent 预设控件旁声明根作用域单值 slot `conversation.hero.pluginDiscovery`。插件清单包通过该 slot 贡献紧凑入口，因此会话包不依赖发现数据或安装行为。

入口打开静态精选目录。入选社区项目必须明确记录官方 `dsh plugin --profile ... add ...` 命令，并提供可识别的开源许可证。卡片展示仓库、许可证、第三方状态、带日期的 Star 档位与项目记录的命令。列表依据当前 GitHub 证据采集，并作为发现指引排序，不会把进入专题当作验证。底部链接进入完整 `dsh-plugin` 专题，供用户继续探索。

每张卡片都提供复制命令与受保护的安装操作。安装前，用户必须明确确认第三方软件包及其生命周期代码会在本机运行。浏览器只发送结构化的 profile 名称与 npm registry 软件包说明符；Host 会拒绝路径、URL、flag 和 shell 文本，再把产品 CLI 的 `dsh plugin --profile ... add ...` 路径作为受管后台进程启动。界面轮询有界任务状态、展示失败诊断，并说明组合包安装成功后需重启 Harness 才会生效。对同一运行中目标的重复点击会复用同一个任务。

安装 Remote 不是通用 shell bridge。它重建当前运行的 dsh 启动器，把固定参数位置交给 subprocess 能力，全程不做 shell 插值。每张卡片仍会提示 Star 不代表 DeepSeek 审核或安全背书，并要求用户安装前检查源码、权限、生命周期脚本与许可证。

## 考虑过的替代方案

- **每次浏览器会话都请求 GitHub：** 未采用，因为专题结果包含无关仓库，未认证限额会降低可靠性，而且实时排名不能证明兼容性或安全性。
- **只复制命令，不提供安装操作：** 未采用，因为这会迫使每位用户离开客户端，重复执行产品已经拥有的命令。受保护的 Host 任务补齐信任决定、进度、失败反馈与去重，同时不暴露任意命令执行。
- **接受任意 pnpm 参数、Git URL 或文件系统路径：** 未采用，因为浏览器载荷届时可以选择精选卡片之外的代码，或改变包管理器行为。首版界面只接受 npm registry 软件包说明符；其他来源继续通过 CLI 使用。
- **在会话组件中硬编码入口：** 未采用，因为生态发现属于插件清单功能，而会话壳已经为独立主页控件提供扩展 slot。
- **列出专题中的全部仓库：** 未采用，因为仅进入专题不能证明项目具有 DSH 安装路径或相关能力。

## 结果

用户可以从主页发现具有代表性的高关注 DSH 项目，检查源码与确切 CLI 命令，明确确认信任后安装，并继续进入更完整的 GitHub 专题。安装沿用 CLI 的 profile 包管理与 bundle 调和语义，而当前进程在重启前保持不变。应用不会在运行时请求 GitHub，也不暴露任意 shell 接口。Star 档位与命令可能过时，因此界面显示采集日期，维护者需要依据项目文档刷新精选记录。
