# Agent Note：会话操作与执行记录

Status: implemented

[English](2026-08-16-conversation-session-actions-and-execution-record.md) | 中文

## 问题

会话页头缺少直接的会话级复制与生命周期操作。逐消息复制已经存在，但导出可见交流内容需要反复操作。用户也需要清空和删除会话，同时不能只在 UI 中隐藏消息、却让同一份模型上下文继续生效。Trajectory 标签页已经包含详细的持久事件，但其名称和首屏没有直接回答智能体实际执行了什么。

## 决策

页头工具提供一键复制已加载的用户／助手对话以及会话菜单。复制内容不包含 reasoning，包含正在显示的助手流式尾部；操作名称明确限定为已加载窗口，因为更早的分页历史可能尚未进入客户端投影。

「清空」与「删除」复用既有的 Workspace 归档操作。「清空」会归档当前会话，并在可能时于同一 Workspace 启动空白会话；「删除」会把会话从客户端列表中移除。两项操作都必须确认，智能体运行时不可用，并明确说明只追加日志仍保留在本地存储中。两项操作都不会一边继续使用同一会话，一边只移除已渲染节点。

Trajectory 标签页打开后会在顶部展示「关键步骤记录」，汇总已加载的轮次数、工具调用数、失败操作数，以及执行中或已记录状态。说明文案明确 Session 日志是数据来源；既有时间线、记录表和检查器继续作为详细证据。

## 曾考虑的替代方案

- **在 React 状态中删除单条消息行：** 不采用，因为模型、回放、分支、导出和查询路径仍会消费持久事件。
- **物理删除会话日志：** 暂缓，因为安全擦除需要由一个能力统一协调活跃会话退出、JSONL 和 SQLite 提供方、Workspace 账目、后代会话、附件及读取投影。
- **为关键步骤建立独立活动存储：** 不采用，因为工具和轮次事件已经持久化，并且是执行记录的权威来源。

## 后果

常用会话流程现在具备快速复制已加载对话、确认后清空和确认后移除的操作。「清空」会生成真正空白的后续会话，而不是保留被隐藏的上下文。「删除」目前表示从列表移除并保留审计数据，弹窗会明确说明这一限制。Trajectory 会先展示即时审计摘要，同时保留完整事件记录表供进一步核对。
