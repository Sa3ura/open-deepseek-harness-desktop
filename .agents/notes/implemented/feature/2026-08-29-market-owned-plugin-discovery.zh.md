# Agent Note: 桌面端拥有插件探索预览

Status: implemented

[English](2026-08-29-market-owned-plugin-discovery.md) | 中文

## 问题

新对话页的插件探索界面维护着第二份固定目录，其中热度数字已经失真，也无法可靠对应当前 Profile。它直接跳转 GitHub，还绕过了负责插件安装、更新、可用性和诊断的产品界面。

## 决策

插件市场继续通过既有目录与安装状态资源提供目录和当前 Profile 状态。桌面对话包拥有版本化推荐与分类四项预览：排除市场自身、已废弃条目和没有安装来源的条目，只按 30 天下载量、Star 和名称排序一次，再单次遍历填充各分类。精简目录投影缓存 24 小时，本机安装状态每次打开都会读取，手动刷新则始终重新校验两个资源。卡片可以深层跳转完整市场条目；拥有明确 npm 包身份的未安装条目在用户确认第三方代码风险后，也可以把结构化包身份交给现有受控安装器。目录里的自由格式命令和仅源码来源绝不会被直接执行。

市场缺失时，客户端仅在用户明确确认后从受校验的内置归档安装。缺少标准市场资源时会如实报告市场不可用或版本过旧。网络与目录失败会如实显示，绝不回退到固定统计数据。插件市场源码不再增加专用探索接口或预览 UI。

市场将普通 npm 安装与注册表比较，将可识别的 GitHub 安装与仓库 HEAD 比较。`file:` 或 `link:` 本地来源默认仍不可更新，除非该包拥有明确可信的发布通道；这个例外允许本地预置的市场发现自身已发布升级，却不会替任意本地插件猜测更新归属。

## 考虑过的替代方案

**保留固定探索卡片。** 这样能立即渲染，但会重复目录、热度与安装状态逻辑，并且必然展示过时或错误事实。

**直接从预览安装。** 这样少一步导航，却会把安装、更新、重启与诊断行为拆到两个界面。预览只负责发现与导航。

**为所有链接包推断仓库。** 包元数据与名称不能证明本地检出可以被远程发布替换。链接包保持本地来源，除非可信发布通道明确拥有这次转换。

## 后果

Electron 与 Web 组合都能显示推荐或分类条目和当前 Profile 状态。用户既可以到完整市场查看任一条目，也可以不离开预览安装 npm 支持的推荐项，同时继续获得标准安装诊断和进度生命周期。有效缓存会避免重复下载目录；缓存过期且刷新失败时只在明确标注后继续展示，安装状态读取失败则显示未知而非未安装。预览排序、过滤、布局、缓存、导航和受控安装入口可以随桌面客户端演进，不再要求插件市场源码为此发布专用功能。
