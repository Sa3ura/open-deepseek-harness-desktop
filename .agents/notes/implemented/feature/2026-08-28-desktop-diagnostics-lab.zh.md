# Agent Note: 桌面诊断演练中心

Status: implemented

[English](2026-08-28-desktop-diagnostics-lab.md) | 中文

## 问题

正式 Profile Doctor 能保护启动，但支持人员仍需要一种可重复的方法，证明某个安装包中的诊断、修复、隔离、恢复和清理确实有效。把单个故意不兼容的第三方插件安装到用户真实 Web Profile，会让演示依赖网络和包管理器历史；中断后还可能留下残留，并且部分安装版根本无法使用该入口。

有效演练必须覆盖多类 pnpm、共享 Host、Loader 和配置故障，又不能接受渲染层传入的任意命令，也不能牺牲被验证的 Profile。重复执行还必须能发现累积残留，而不是只报告某一轮看起来成功。

## 决策

桌面宿主通过窄范围 Electron Bridge 提供版本化“诊断演练中心”。目录包含九个固定场景标识和固定样本字节：兼容与不兼容 Host 影子副本、孤立 Bundle、缺失模块、无效 Patch、重复 Loader、生命周期失败、构建许可被阻止和修复中断。渲染层只能选择这些标识、`quick`、`standard`、`soak` 档位，以及隔离环境或需明确确认的真实 Profile；不能传入包名、路径、命令、脚本、环境变量或样本内容。

默认目标会在 Electron `userData` 下创建本次运行专属的 home。每轮固定经过六个可观察阶段：健康基线、注入、检测、修复或隔离、复检和清理。注入后会用内置 SHA-256 校验样本字节。结果保留预期与实际产品错误码、修复处置、清理结果、耗时和经过限长脱敏的诊断。成功、断言失败和取消都会删除运行时数据；JSON 与文本报告保留在桌面日志目录。

每个阶段都会真正跨过正式 `dsh plugin --profile web doctor` 子进程边界，不用延时器伪装压力。兼容 Host 影子副本、不兼容 Host 依赖和孤立 Bundle 还会通过内置 pnpm 的离线模式在隔离 Profile 中构造真实依赖图；样本包归包管理器管理，而不是手工塞进 `node_modules`，因此正式修复操作能够真正重新链接或移除它们。兼容场景必须返回 `repaired`，不兼容与孤立场景必须返回 `quarantined`，随后每个场景都必须通过只读复检。Loader 与配置类样本目前验证的是闭合的桌面分类和恢复契约，同时执行正式 Doctor 基线检查；文档不会把它们描述成正式 Loader 激活测试。

高级目标必须主动选择，并在写入前暂停受监管 Harness。它会备份白名单内的 Profile 清单、Workspace 策略、Patch、隔离记录和健康报告，同时保存哈希与写前恢复日志。演练数据使用命名空间隔离的 `.diagnostic-lab/<runId>` 目录，不复制或采用用户 `node_modules`。每一轮进入下一轮前都会校验并恢复受管字节。无法安全归因的哈希变化视为外部编辑：演练停止、恢复日志保留，并且不会重启 Harness。应用下次启动时必须先处理未完成日志，之后才允许加载 Profile 插件。

高级目标只提供可以事务恢复的场景。损坏 Patch、生命周期执行、构建脚本许可和受控中断仍只允许在隔离环境运行。取消只会在场景安全边界生效，因此清理和最终健康检查仍会执行。Manager 在单个进程内串行运行；正式插件操作仍是权威路径，演练中心不会新增通用包管理器或文件系统 IPC。

## 曾考虑的替代方案

**保留仅源码可用的“安装诊断测试插件”按钮。** 否决，因为它只覆盖一种不兼容依赖，会修改真实 Profile，依赖源码路径、网络和包管理器状态，并且在安装版中可能点击后毫无反馈。

**允许渲染层组合任意故障包或 Shell 命令。** 否决，因为这会让 Web 客户端获得通用代码执行和文件系统权限。闭合目录和固定字节把权限保留在桌面主进程。

**让所有破坏性场景都运行在真实 Profile。** 否决，因为无效 Patch、生命周期和构建脚本无法像命名空间清单与 Loader 样本一样可靠恢复。这些场景必须留在可丢弃 home。

**演练后整体恢复 Profile 或 `node_modules`。** 否决，因为这可能覆盖并发用户修改、复制平台相关包状态，并掩盖演练实际改动了哪些字节。恢复日志只拥有小范围白名单，遇到意外哈希就拒绝覆盖。

## 结果

开发版与安装版现在使用同一套离线演练入口，支持人员可以区分“诊断断言失败”和“清理或恢复失败”。标准与耐久档分别连续执行三轮和十轮，使残留与幂等问题可见。报告不会携带用户名、凭据、Token、私有仓库认证、任意环境变量值或无限堆栈。

该功能增加了桌面自有样本、恢复日志、第二套设置工作流和一项明确的失败关闭启动依赖。隔离场景验证桌面端的分类与恢复编排；它不会把任意第三方生命周期脚本变成安全代码，也不会替代正式 Doctor 证据。真实 Profile 演练会暂时停止 Harness，因此它是高级排障操作，而不是后台健康检查。

活动任务由 Electron 主进程持有，而不是由 Harness 渲染页面持有。新增 `current` Bridge 操作后，Harness 维护重载产生的新页面可以重新接回原任务；根级 `shell.overlay` 任务卡复用右下角插件安装卡的呈现方式，显示当前场景与步骤、总轮数与剩余轮数、通过和失败数量以及安全取消。隐藏任务卡只影响展示，不会终止主进程中的演练。

聚焦测试固定目录校验、串行所有权、隔离清理、三轮重复、真实 Profile 暂停与字节恢复、报告脱敏、Supervisor 维护后恢复、受限 Preload Bridge、设置页呈现和主题滚动条。本桌面能力的验证通道不包含浏览器回放或 Playwright。
