# Agent Note：可选的桌面端自有 `dsh` 命令注册

Status: implemented

[English](2026-08-25-desktop-dsh-command-registration.md) | 中文

## Problem

桌面安装包已经携带完整的目标平台 Node、Harness 与 pnpm 运行时，但用户只能通过图形应用访问。把全部私有可执行文件加入 `PATH` 虽然方便，却会与系统 Node、Corepack、nvm、fnm、Volta 或官方 `dsh` 安装冲突。终端启动器也不能固定假设使用 `~/.dsh`，因为桌面端可能使用全新或导入的独立 home，也可能明确复用官方 home。

## 决策

**桌面端只可选注册 `dsh`。** Windows 提供默认不勾选的安装页面，以及“通用设置”中对应的控制。注册只把一个精确的应用资源目录前置到当前用户 PATH；静默安装只有 `/ADDCLI=1` 会启用。macOS 由“通用设置”向 `.zprofile` 或 `.bash_profile` 写入一个带标记的 PATH 区块，并保留一次备份；无法识别的 Shell 不会被修改。移除时只处理 Windows 中精确的自有条目或 macOS 标记区块。

**Windows 在实际安装段中读取静默安装选项。** Assisted NSIS 安装器可能在初始化后跨越外层／内层实例边界，因此真正执行安装的阶段会再次解析 `/ADDCLI=`，而不是只依赖 `customInit` 写入的变量。安装详情会记录最终选择和注册失败原因。静默注册失败也不会等待一个不可见的消息框；应用安装可以结束，同时保留可诊断的可选命令缺失状态。

**PATH 持久化不会再同步等待每一个桌面窗口。** Windows 辅助脚本直接写入当前用户的 `HKCU\Environment\Path`，并保留既有注册表值类型，随后用异步 `SendNotifyMessage` 发送 `WM_SETTINGCHANGE`。这避免了 `.NET` 环境变量持久化再叠加 `SendMessageTimeout(HWND_BROADCAST, ...)`，从而不再因为某个无响应窗口让静默安装器卡住数分钟、且迟迟无法写入可选命令注册标记。

**终端命令是窄权限的应用自有启动器。** 它使用内置 Node、Harness 入口与 pnpm 入口的绝对路径，以参数数组转发给不经过 Shell 的子进程。npm 与 pnpm 继续作为私有实现细节，也不会写入全局 `DSH_HOME`。渲染层只能通过固定 IPC 操作查询状态、安装或修复、移除，不能传入路径、可执行文件、脚本或命令。

**每次调用都以已保存的桌面数据目录选择为准。** 启动器读取安装版的 `data-home-setup.json`：全新与导入模式使用桌面独立 home，复用模式使用选择页记录的官方 home。尚未选择、记录损坏或内置运行时缺失时，会失败并提示打开桌面端修复；绝不会创建回退目录来掩盖环境分裂。

**已有命令的所有权必须经过确认。** 状态会报告 PATH 中发现的每个非本应用 `dsh`。安装默认保持取消，只有用户明确强制确认后，桌面入口才会遮蔽原命令。应用升级会刷新已经注册的 macOS 启动器，但不会在 Shell 区块不存在时擅自添加。

## 曾考虑的替代方案

- **暴露内置 Node、npm 与 pnpm：** 否决。私有包管理版本属于应用运行时，不是受支持的用户工具链，而且会与既有版本管理器竞争。
- **安装时始终注册 `dsh`：** 否决。命令优先级是持久外部状态，且名称可能已经属于官方命令。
- **设置全局 `DSH_HOME`：** 否决。那会改变官方 CLI 与其他进程的行为，而不是只为当前启动器选择数据。
- **发布 macOS PKG 或修改 `/usr/local/bin`：** 否决。现有 DMG 保持用户级安装，不应只为一个可选命令要求提权。
- **安装启动器时只解析一次数据目录：** 否决。用户可以通过桌面选择记录在独立与复用数据之间切换；调用时解析才能让命令始终与客户端一致。

## 影响

- 用户可以从 Windows 安装过程或“通用设置”、以及 macOS“通用设置”选择启用 `dsh`，无需安装系统 Node 或 pnpm。
- PATH 配置改变后需要新开终端。macOS zsh 与 bash 可自动处理；其他 Shell 会显示不支持状态，不作危险猜测。
- 移动或不完整删除应用时会产生损坏状态和修复路径，不会静默回退到另一个 `dsh`。
- Linux 保持不变，直到其包格式对应的 PATH 所有权与卸载约定完成设计。
- 单元测试固定设置解析、参数转发、退出行为、路径冲突、macOS 备份与幂等、Windows 精确当前用户 PATH 操作及移除。Windows 安装包烟雾测试会显式启用命令，从含空格和中文的路径运行已安装启动器，并要求卸载后恢复原始用户 PATH。
