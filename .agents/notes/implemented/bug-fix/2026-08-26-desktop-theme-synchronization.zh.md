# Agent Note: 让桌面启动界面与当前主题同步

Status: implemented

[English](2026-08-26-desktop-theme-synchronization.md) | 中文

## 问题

Web 客户端会持久化内置主题偏好，但 Electron 启动文档以及原生或自定义窗口边框各自跟随操作系统外观。当浅色系统使用固定深色主题，或深色系统使用固定浅色主题时，数据目录选择页、加载页、首次引导、主界面和顶栏之间会出现明显的配色跳变。

## 决策

当前 Harness 数据目录继续作为持久化 `ui-theme.preference` 的权威来源。桌面宿主在创建主窗口前读取该字段，并把每个内置皮肤映射为 `system`、`light` 或 `dark`；展示状态缺失或格式损坏时回退到 `system`，但不会阻止诊断功能报告设置错误。Electron 原生主题与窗口预绘制背景使用解析后的来源，因此加载页和原生边框会在 Web 客户端就绪前保持一致。

Web 主题呈现器在继续拥有解析后调色板和 token 的同时，把同一个三值来源发布到 document 根节点。沙箱 preload 只观察这个受限属性，并通过窄范围 IPC 通道发送。主题切换由此可以更新 Electron 边框，同时不会向渲染进程暴露设置、文件系统或任意样式操作。`system` 与其当前解析出的明暗结果保持不同，因此后续操作系统外观切换仍能实时生效。

首次数据目录选择页尚未拥有选定的 Harness 数据目录，因此跟随操作系统外观；它的静态文档提供完整的浅色和深色样式。首次引导位于 Web 客户端内部，会继承与主界面相同的主题快照。

## 考虑过的替代方案

**让每个启动页面独立使用 `prefers-color-scheme`。** 这种方式无法表达与操作系统不同的显式应用主题，也是原有错位的原因。

**把 Electron 固定为最近解析出的浅色或深色。** 如果把 `system` 当作固定值，后续操作系统外观变化就无法继续传递。

**通过 preload 暴露完整主题注册表或设置 API。** 桌面边框只需要三值来源。更宽的 bridge 会复制主题所有权并扩大渲染进程权限。

## 后果

初始化、加载、首次引导、主界面、BrowserWindow 预绘制像素和窗口边框使用一致的明暗基础。自定义皮肤继续保留 Web token 覆盖，而 Electron 只消费其基础配色。由于 Web 运行时在早期启动阶段尚不可用，桌面宿主会维护一个小型只读解析器来读取持久化偏好。
