# Agent Note：保持设置操作与插件导航可访问

Status: implemented

[English](2026-08-29-settings-native-open-and-navigation-overflow.md) | 中文

## 问题

设置文档操作使用原生路径打开器，而其 Windows 适配器通过裸命令名 `powershell.exe` 启动程序。Host 的 `PATH` 受限时，即使 Windows 和文件关联均可用，该按钮仍会失败。设置导航也没有受高度约束的滚动子项，因此超出面板高度的插件设置分类会被面板的 overflow 规则裁掉。

## 决策

原生 Windows 从 `SystemRoot` 解析系统自带 PowerShell 的绝对路径，并依次使用 `WINDIR` 与标准 Windows 目录作为回退。适配器继续使用无 shell 的 argv 执行；只有 WSL 互操作保留裸命令名，因为 Linux 进程无法直接寻址原生 Windows 文件系统路径。

设置导航栏把标题保留在独立滚动区之外。导航栏和列表可以在受限高度的 flex 列中收缩，而每个插件贡献项保持完整行高。滚动区会限制滚轮越界传播，并预留稳定的主题滚动条空间。设置遮罩的固定位置和面板最大高度会扣除桌面标题栏 inset。

后续检查把同一安全区契约应用到经 portal 挂到 `body` 的共享 `Modal`、首次引导接管层、连接横幅、附件拖放遮罩和图片灯箱，将默认弹窗内容约束为内部滚动区，并让多列设置向导的左右两侧都具备受限滚动。这会覆盖绕过已下移应用根节点的全窗口表面，并确保矮窗口或高显示缩放下仍可触达操作控件。

## 后果

打开设置文档不再依赖继承到的 Windows PATH 项。任意数量的插件设置分类都可通过鼠标、滚轮和键盘焦点访问，同时设置标题保持固定。经 portal 渲染的配置弹窗也会保持在自定义窗口边框下方，并限制在可用高度内。普通浏览器使用零标题栏 inset，桌面 preload 则提供自定义边框对应的数值。
